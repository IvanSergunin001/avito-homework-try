# Конфигурации кодогенерации

Один файл на связку «спецификация → пакет». Все они прогоняются одной командой
`make api`: она собирает `bundle.yaml` каждой поверхности и генерирует по ним код.
Генерация идёт от собранного документа, а не от дерева `$ref`-ов, — так результат не
зависит от того, как кодогенератор разрешает внешние ссылки.

| Конфигурация | Из чего | Что порождает |
|---|---|---|
| `platform_customer.yaml` | `api/customer/v1` | серверный интерфейс клиентской поверхности площадки |
| `platform_partner.yaml` | `api/partner/v1`, операции с тегом `platform` | серверный интерфейс партнёрской поверхности площадки |
| `platform_admin.yaml` | `api/admin/v1` | серверный интерфейс админской поверхности площадки |
| `platform_restaurant_client.yaml` | `api/partner/v1`, операции с тегом `restaurant` | клиент, которым площадка ходит в заведение |
| `restaurant_partner.yaml` | `api/partner/v1`, операции с тегом `restaurant` | серверный интерфейс партнёрского контракта в коробке заведения |
| `restaurant_platform_client.yaml` | `api/partner/v1`, операции с тегом `platform` | клиент, которым коробка ходит в площадку |
| `restaurant_operator.yaml` | `api/operator/v1` | серверный интерфейс рабочего места оператора коробки |

Партнёрский контракт описывает обе стороны интеграции одним документом, поэтому из него
генерируются четыре разных артефакта: по серверу и клиенту на каждую сторону — площадка
реализует свою половину и зовёт чужую, коробка делает то же самое зеркально. Разделяет
их тег операции.
