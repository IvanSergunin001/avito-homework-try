# ADR — записи об архитектурных решениях

Здесь лежат решения, которые дорого отменить и по которым ревьюер обязан задать вопрос
«почему так?». Всё остальное — обычные решения кода, они объясняются комментарием рядом
с собой, а не отдельным документом.

Формат у всех записей один: контекст (что вынуждало решать), решение, последствия
(включая неприятные), рассмотренные и отклонённые варианты и то, что меняется в
эксплуатации. Записи не правятся задним числом: решение, которое перестало быть верным,
отменяется новой записью, а старая остаётся с пометкой в статусе — иначе по репозиторию
нельзя восстановить, что и почему думали в момент выбора.

| [0002](0002-synchronous-order-placement.md) | Оформление заказа — синхронный вызов заведения, а не двухфазный резерв |
| [0003](0003-order-items-inside-aggregate.md) | Позиции заказа живут внутри агрегата документом, а не отдельной таблицей |
